# Security policy

This repository is primarily documentation, but executable helpers and Agent Skill instructions can still create supply-chain or data-handling risk.

## Report privately

Use GitHub's **Security → Report a vulnerability** flow when available. Do not include secrets, private customer data, exploit details, or personal contact information in a public issue.

For ordinary documentation mistakes, broken links, expired guidance, or incorrect examples, use the playbook feedback issue form instead.

## In scope

- A tracked script that exposes, transmits, or modifies data unexpectedly
- Skill instructions that request credentials or private data without a legitimate need
- Command injection, unsafe file handling, or an undeclared network call
- A committed credential or sensitive customer artifact

The maintainers will acknowledge valid reports, assess whether public guidance or a release is affected, and document the correction after a safe fix is available.
