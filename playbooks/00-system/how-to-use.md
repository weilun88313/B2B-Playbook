# How to use the library

## Use one module at a time

Choose the work that is actually in front of you:

- You cannot say who should buy → [ICP](../01-icp/)
- The homepage or sales story is unclear → [Positioning](../02-positioning/)
- You need to start qualified conversations → [Outbound](../03-outbound/)
- You are deciding whether to attend or sponsor an event → [Event-led growth](../04-events/)
- You have a first meeting and need to reach signature → [Enterprise sales](../06-sales/)

## Read a module in this order

1. `README.md`: confirm the use case and exclusions.
2. `sop.md`: follow the entry criteria, steps, and exit criteria.
3. Copy the relevant file from `templates/` into your own workspace.
4. Compare it with `examples/` to calibrate completion density, not industry choice.
5. Run `checklists/` before the external action.
6. Use `metrics.md` to choose one to three signals for the next review.

## Completion standard

See the [quality contract](../../README.md#quality-contract). A principles-only essay is not a complete playbook.

## The Helion example

Helion is a fictional supplier due-diligence software company. It gives templates enough detail to be useful without exposing a real customer. Replace its buyer, trigger, and alternative with your own evidence; do not rewrite the operating logic merely to copy the example's industry.
