# Content strategy

**Last reviewed:** 2026-08-28

Content strategy is the decision of which buyer questions deserve a durable page—and in what order—so sales can send a link that helps an evaluation move.

Volume, calendars, and “thought leadership” are production systems. They only become demand generation when a champion can use the asset to explain the problem, compare a real alternative, or answer an internal objection.

## Use this when

- The team does not know which site pages to write first.
- Traffic or posting cadence is rising, but qualified sales conversations are not.
- Comparison or category pages are being drafted as feature tables.
- Founders want a content engine before the market’s decision questions are named.

## Do not use this when

- The ICP and current alternative are still empty. Complete [ICP](../01-strategy-and-buyers/icp.md) and [positioning](../02-product-marketing/positioning.md) first.
- The real goal is to replace outbound or a first conversation with a blog.
- The request is “publish three times a week” with no decision question attached.

## Operating method

### Step 1: collect decision questions, not interest topics

Ask sales (or review the last ten serious conversations) for the questions buyers ask when they are deciding whether to continue. Write each as a buyer-voiced question. Typical shapes:

- Can we keep doing this with the current process or spreadsheet?
- How should we choose between this category and the incumbent system?
- Do we have to replace another platform first?
- Where does the data live, and what will security review actually ask?

Do not start from “what would this audience find interesting.” Interest is not a buying motion.

### Step 2: sequence decide, then educate

Default build order for owned pages:

| Order | Job of the page | Search or forward intent |
|---|---|---|
| 1 | Category and seat: who this is for, and which job it finishes | `{category} for {role}` |
| 2 | Alternative: when the current way stops being enough | `{status quo} is not enough` / when to switch |
| 3 | Comparison: how to choose among options that already appear in deals | `{you} vs {alternative}` / `{alternative} alternative` |
| 4 | Constraint: the line a blocker will check | security, deployment, implementation scope |
| 5 | Education: long-form only if a champion can still cite it | narrative, research, or category point of view |

A full editorial calendar that leaves rows 1–3 empty is a content performance, not a content strategy.

Brand narrative, founder story, and thought leadership still matter. They are later rows unless a live deal is already blocked on a missing evaluation page.

### Step 3: one page, one question

Complete one topic brief per page. The page may have only:

- one primary question;
- one primary buying-committee seat;
- one next step (a scoped demo, a sample, or forwarding the comparison page).

“A complete introduction to the platform” is not a primary question.

Comparison structure stays in the [positioning comparison-page outline](../02-product-marketing/positioning.md#comparison-page-outline) until the website playbook for comparison pages is published. This playbook decides whether that page exists and which alternative it covers.

### Step 4: name the working artifact

Before writing, answer: will sales drop this URL into an evaluation thread? If not, the page is brand or education. That can be valid, but it is not demand generation and should not occupy the first four rows.

A comparison page must let a champion discuss the conditions under which each option wins.

### Step 5: refuse unfinished pages

Run the pre-flight checklist. A page that fails it is a draft, not a published asset.

## Pre-flight checklist

- [ ] The primary question is a buyer question, not a product introduction.
- [ ] The primary seat is named. “All B2B” is not a seat.
- [ ] The alternative or comparison object already appears in sales conversations.
- [ ] The page has one primary action.
- [ ] A likely blocker can find the relevant constraint, or the page states that the constraint lives at another URL.
- [ ] No invented customer names, percentages, awards, or unnamed case studies.
- [ ] Sales can finish the sentence: “I send this link when _____.”
- [ ] The title matches language a buyer would search or forward, not an internal project name.

## Metrics

| Metric | Diagnostic use |
|---|---|
| Sales forwards | Times an AE or founder pastes the URL into an evaluation thread or follow-up—not self-traffic in analytics |
| Page → conversation | Qualified conversations within 14 days after the page was used as the next step |
| Map completeness | Whether rows 1–4 each have a page that passed the checklist |
| Question drift | Whether the live title still answers the brief’s primary question |

Impressions, AI citations, and time on page are diagnostics for “can anyone find this.” They are not success. Publishing cadence, “brand conversation,” and likes on educational posts do not measure this playbook.

## Common mistakes

- Filling a calendar instead of the decision-page map.
- Writing for a persona’s hobbies rather than a committee seat’s objection.
- Building comparison pages against a famous vendor the team never actually loses to.
- Leading with thought leadership while category, alternative, and comparison pages are missing.
- Counting traffic as pipeline because the URL was on a blog subdomain.

## Sources and evidence boundary

This is an owner-maintained operating synthesis. It does not claim a universal content ROI model. Proof on any live page must stay inside dated, checkable product, customer, security, and performance evidence. Fictional companies and anonymous “case studies” are not evidence.
