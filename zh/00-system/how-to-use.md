# 如何使用

## 一次只用一块

不要按目录从头读到尾。选你本周真实在做的事：

- 还说不清卖给谁 → [01-icp](../01-icp/)
- 官网或销售口头说不清 → [02-positioning](../02-positioning/)
- 要主动约会议 → [03-outbound](../03-outbound/)
- 正为某场展会花钱或派人 → [04-events](../04-events/)
- 已经约到会、要走到签字 → [06-sales](../06-sales/)

## 每个模块的阅读顺序

1. `README.md`：不准用的场景先看，避免套错方法
2. `sop.md`：按准入 / 步骤 / 准出做
3. 复制 `templates/` 到你自己的工作区（Notion、Doc、CRM 备注均可）
4. 对照 `examples/` 看「填满长什么样」，不要抄示例里的行业当自己的 ICP
5. 对外动作前过 `checklists/`
6. 用 `metrics.md` 决定本周看哪 1–3 个数

## 一篇写完的标准

见仓库根目录 [CONTRIBUTING.md](../../CONTRIBUTING.md)。原则文不算完成。

## 示例里的 Helion

Helion 是虚构的供应商尽职调查产品，用来让模板有血肉。它不是本仓库的产品，也不代表你应该卖这个品类。换行业时只换示例里的触发因素、角色和替代方案，不要换 SOP 结构。
